# WebUI 主题、导航与输入法修复（2026-11-20）

针对 v0.4.3 用户反馈的颜色不统一、底栏切换生硬、Canvas 输入框不能稳定唤起手机键盘及键盘弹出抖动，修改 WebUI 源码。

## 实现

- 使用 Miuix `MonetSystem` 加固定蓝色种子生成完整深浅色板，而非只覆盖 primary。这里是固定种子配色，不读取手机壁纸。状态卡使用 primaryContainer/onPrimaryContainer；输入层通过 CSS 变量使用同一个已解析色板，跟随运行时主题变化。
- 悬浮容器中恢复 Miuix `NavigationBar`/`NavigationBarItem`，采用组件自带的图标位置与文字透明度动画；选中背景另有 300ms 平移，页面内容使用 180ms Crossfade。每页有独立滚动状态。
- 名称、密码直接打开 DOM input，不再要求先操作 Canvas 文本框或再选备用输入。输入框在点击调用栈中同步 focus，提供真实的可编辑元素与点击机会。校验继续调用 Kotlin 的 SSID/密码规则，提交仍经原控制器生成十六进制固定命令。
- 中文 composition 期间禁止提交；取消/保存清空 DOM 值；提供对话框角色、输入标签、错误提示与焦点循环。底层保存门禁拒绝时保留输入并提示。
- 输入弹出时临时固定背后 Canvas 尺寸并设为 inert，关闭恢复。输入层只按 visualViewport 的 height/offsetTop 调整，resize/scroll 用 requestAnimationFrame 合并；不对键盘几何变化添加 CSS 过渡，不重复 focus 或 scrollIntoView。

## 验证边界

生产 Wasm 和字体生成通过，未变化的 33 项 JVM 逻辑测试保持通过（Gradle up-to-date）；26 个 Chromium 场景全部通过。浏览器覆盖名称/密码的原生焦点与保存、非法密码、中文 composition Enter 不提交、可视高度按 760/640/520/440 像素变化时输入可见且 Canvas 尺寸固定、打开输入层时切换主题、关闭后恢复 Canvas，以及导航动画中间帧。最终 webroot 树哈希为 `eefe858633c3f375b4cf4e9da9f560e95cc343b069d2b22e2b50d09318730f63`。

桌面 Chromium 的视口缩放不是 Android 输入法。未调用 ADB、未安装模块，不据此宣称已验证 KernelSU WebView 的 IME 弹出、候选栏、返回键与键盘动画帧率。需后续在用户实际管理器/WebView/输入法组合确认，特别是横屏与极短可视高度。
