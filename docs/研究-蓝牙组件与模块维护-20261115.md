# 蓝牙组件与模块维护（2026-11-15）

## 2026-11-16 更新：热点动态状态卡

热点 v0.2.24-dijun.1 新增与 6GHz 相同形式的 `module.prop` 描述卡：热点状态、频段、配置带宽、热点密钥/恢复配置是否就绪、SELinux、恢复结果、最近操作及更新时间。只输出固定状态词和返回码，不展示凭据、网络身份或原始日志。

复用既有请求 worker 约每 30 秒调用原控制器的只读状态入口，跳过正在执行的动作；快照发布与操作结束也会更新。禁用 worker 时仅事件更新，允许显式只读刷新。没有新增 daemon。过期或上一 boot 的快照不会显示为运行；一次渲染捕获一份快照，避免并发替换时拼出混合状态。

完整性沿用 6GHz 的静态模板设计，只允许动态描述变化。卡片失败不影响热点原有返回码。快照 schema v3 保持十个字段，不改变旧 Settings 解析器协议。

[模块使用说明](../modules/mt6639-hotspot/README.md) · [发布候选与校验值](https://github.com/xiatian410/mt6639-wifi7-dijun/releases/tag/hotspot-v0.2.24-dijun.1)。本次增加离线状态与生命周期测试，不增加无线硬件兼容结论。 新增 15 项状态卡测试；完整离线套件 480 项，432 通过、48 按已有依赖条件跳过，零失败。热点使用已固定校验的构件执行了两次打包，可重复性测试通过。

## 蓝牙 v0.2.0-dijun.1

原实现只接受 OS4.0.0.19 的完整 fingerprint，并固定 Bluetooth APEX 内的应用目录版本。已知新版正式版 APK 改变后，即使六个 Host 入口仍可使用也会被拒绝。

本批从已有原厂 OS4 初始版和 OS4.0.4 完整镜像只读提取 `/system/apex/com.android.bt.apex`，再用 `debugfs` 导出其 payload 中的 Bluetooth APK。原件、反汇编和本地日志不进入 Git；[公开派生摘要](bt-component-comparison.json) 只有组件哈希与方法比较结果。

| 组件 | 初始版 | OS4.0.4 |
| --- | --- | --- |
| APK 字节数 | 11701770 | 11722250 |
| APK SHA-256 | `22f2e2ac8c036f7716e792f1fa54d7f5c3dd53754cb3c01db93ee3981cd34339` | `1a5ae65ccd8621c03ca5a6a035979eac74025c3ecdda19dd84f1bbd53162983e` |
| 七个 `isEnabled` 方法 | 比较基线 | 归一化后相同 |
| `Config` 单播注册条件 | 原 `LeAudioService.isEnabled()` | 新增厂商 UMS 开关与原条件相或 |

七个方法覆盖 LeAudioService、LeAudioBroadcast 与其 Kotlin Companion、BassClientService、CsipSetCoordinatorService、VolumeControlService、McpService。使用 Debian baksmali 2.5.2 反汇编，保留解析后的引用、指令和控制流，仅移除 `.line` 等调试信息及空白；摘要不是整个 DEX 或音频协议栈等价证明。新版仍可通过原六项非持久属性进入这些 Host profile，不需要改厂商持久 UMS 开关。

实现变化：

- 检查 dijun、SDK 37、活动 APEX 中唯一 APK 与已核对哈希，取消 OTA 完整 fingerprint 限制。APEX 应用目录版本可变，未知/缺失/多候选/不可读组件均有明确诊断。
- 保留 LE Audio offload 的原始前提；只改原六项非持久属性，不改驱动、控制器能力、配对信息或 offload 配置。
- 状态从 shell 域有界查询 `settings`，调用失败或异常返回显示 `unknown`。
- 恢复失败发布 `restore_failed`，操作按钮随后重试恢复；状态文件原子替换。恢复不受新 APK 的启用门禁阻断。
- 验证状态目录所有者与 `0700`，拒绝符号链接锁和标记。快照继续按 boot 隔离，旧记录保留。

这表示相同受支持组件可跨 OTA 继续运行，**不表示未知组件、当前手机 APK 或所有未来 OS4 更新已经验证**。属性成功不等于进程已加载 profile；若蓝牙已开启，仍需等待正常蓝牙开关周期，模块不会自行断开音频。

## 热点 v0.2.23-dijun.1

`request_worker.sh` 已有私有目录检查，直接运行 `control.sh` 却只做 mkdir/chmod，且忽略失败。现在直接入口也先验证父目录、目录类型、所有者，拒绝符号链接和文件；新建及权限修改失败立即退出，成功后回读 `0700`，然后才处理日志、锁和会话。

同时将模块描述压缩为当前行为和限制，历史版本流水保留在 Git，不再把长篇历史放进管理器描述。没有改热点频段、国家码、功率、驱动、连接或恢复判定逻辑。

## 有限验证与构建

- 原蓝牙控制入口测试扩展到 16 项，覆盖组件和事务恢复。Android 属性/Binder/身份等 I/O 为夹具，真实状态转换和失败处理执行生产脚本。
- 蓝牙打包 2 项：源码字节、权限、清单、可重复性和拒绝覆盖/符号链接/凭据。
- 热点真实控制脚本前导段 1 项包含七类目录状态；未执行无线操作。
- 完整离线套件共 465 项，416 通过、49 项因已有构件/Android 依赖缺失跳过，零失败。没有重跑未变的原厂驱动比较或上次 6GHz 实机链。

```sh
python3 tools/build_bt_module.py /absolute/path/to/NEW-bt.zip
```

蓝牙 ZIP 仅包含维护脚本与文档，无原厂 APK、固件、用户日志、MAC/SSID、凭据或配对数据。运行后生成的本地快照不是分发内容。热点构建依赖继续使用上游已固定校验的构件，不能用任意同名文件替换。
